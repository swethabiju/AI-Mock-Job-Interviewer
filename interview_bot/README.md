# Mock Job Interviewer (HR + Technical + Coding) - fine-tuned Qwen2.5-1.5B

A chatbot that runs three kinds of practice interviews. The model is **fine-tuned by you** (QLoRA); no API is called.

**Design in one line:** code does the checking (STAR markers, key-point checks, unit tests, scores); the fine-tuned LLM
is the conversational policy (right action tag, one question per turn, correct hint level, no code leaks, valid scorecard JSON).

## Run it (Google Colab)
1. Colab -> **Runtime -> Change runtime type -> T4 GPU**. (Default is CPU. Training on CPU will not finish.)
2. File -> Upload notebook -> `01_train.ipynb`. Run all cells. When asked, upload `interview_bot.zip`.
   Expected: roughly 30-60 minutes on a T4 *(estimate, not measured)*.
3. File -> Upload notebook -> `02_eval.ipynb`. Run it **in the same session** (so the `adapter/` folder exists).
   It compares the prompted base model against your fine-tuned model on held-out test conversations.
4. Last cell of `02_eval.ipynb` launches the chat app and prints a public link.
   `python app.py --dry` runs the app without the model (rule engine only) for UI testing.

## What is in the box
| File | Purpose |
|---|---|
| `seeds.py` | Roles, HR questions, 14 technical questions with key points, 10 coding problems with tests and buggy variants |
| `core.py` | Checkers, safe code runner, session controllers, scorecards (the "brain" that is verifiable) |
| `gen_data.py` | Simulates candidates and writes `data/train|val|test.jsonl` (1100 / 90 / 108 conversations) |
| `metrics.py` | Scores every model reply (format, action, content, leaks, false pass, scorecard validity and error) |
| `app.py` | Gradio app |
| `01_train.ipynb`, `02_eval.ipynb` | Training and evaluation |

## Held-out test design
Test conversations use questions/problems the model never saw in training (2 HR questions, 3 technical questions,
2 coding problems) and messy candidate phrasing (lowercase, typos, filler words). You must also add your own 20+ handwritten messy
answers (last section of `02_eval.ipynb`) and report them separately.

## Report checklist
- Disclose that the training data was generated by script from seed banks I (an AI assistant) helped write, and that AI helped write the code.
- Show: loss curve (`loss_curve.png`), results table (`results.csv`), comparison chart (`comparison.png`), failure examples, handwritten-test results.
- Say plainly: the app's flow is controlled by the rule engine; the model's action accuracy is measured separately (`action_match`).
- Limitations: simulated data is repetitive; keyword checks are crude for real human answers; 1.5B model; coding mode runs candidate code locally.

## Troubleshooting
- **CUDA out of memory:** in the training cell set `per_device_train_batch_size=1` and `gradient_accumulation_steps=16`, or lower `MAXLEN` to 1280.
- **Colab disconnects:** the last training cell copies `adapter/` to your Google Drive; re-run `02_eval` after copying it back.
- **Evaluation too slow:** set `LIMIT = 150` in the eval notebook for a quick pass, then run the full set later.
- **Library version error:** paste the full traceback to your assistant.
